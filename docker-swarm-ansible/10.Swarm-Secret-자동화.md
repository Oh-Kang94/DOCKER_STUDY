# 10. Swarm Secret 자동화

## Ansible Vault와 Swarm Secret

| 도구 | 보호 구간 |
|---|---|
| Ansible Vault | Git·Inventory·Variable File에 저장된 값 |
| Swarm Secret | Manager Raft Log와 실행 Task로 전달되는 값 |

Vault로 암호화한 값도 Playbook 실행 중에는 복호화되어 Swarm에 전달된다. 두 도구는 서로 대체 관계가 아니라 입력 저장과 Runtime 전달을 각각 보호한다.

```yaml
- name: Database Password Secret을 생성한다
  community.docker.docker_secret:
    name: "db-password-{{ secret_version }}"
    data: "{{ vault_db_password }}"
    state: present
  no_log: true
```

## Service에서 사용

```yaml
services:
  api:
    image: registry.infra.local/apps/api@sha256:<digest>
    secrets:
      - source: db_password
        target: db_password

secrets:
  db_password:
    external: true
    name: db-password-2026-07
```

Container에서는 기본적으로 `/run/secrets/db_password` 파일로 읽는다. 환경변수로 복사하면 Process 환경과 Debug 출력에 노출될 수 있으므로 Application이 File 입력을 지원하게 한다.

## Rotation

Swarm Secret은 내용 수정 대신 새 Secret을 만든다.

1. 외부 시스템에서 새 Credential을 발급한다.
2. 새 이름의 Swarm Secret을 생성한다.
3. Service가 새 Secret을 사용하도록 Rolling Update한다.
4. 새 Credential 동작을 확인한다.
5. 이전 Credential을 폐기하고 이전 Secret을 제거한다.

DB가 두 Credential을 동시에 허용하지 않으면 Application 중단 없이 전환할 별도 절차가 필요하다.

## 노출 방지

- Secret 관련 Task 전체에 `no_log: true`를 적용한다.
- `--diff` 출력과 Callback Plugin이 값을 기록하지 않는지 확인한다.
- Vault Password 파일을 저장소에 Commit하지 않는다.
- Manager Backup과 Autolock Key를 민감자료로 관리한다.
- Secret 값을 Checksum 이름으로 그대로 유추할 수 있게 만들지 않는다.
