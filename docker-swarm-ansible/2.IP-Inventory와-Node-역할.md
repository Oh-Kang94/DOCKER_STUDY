# 2. IP Inventory와 Node 역할

## Inventory 구조

```yaml
all:
  vars:
    ansible_user: ops
    ansible_become: true
    ansible_ssh_private_key_file: ~/.ssh/swarm_ed25519
  children:
    swarm_managers:
      hosts:
        manager-01:
          ansible_host: 10.10.0.11
          swarm_data_addr: 10.20.0.11
        manager-02:
          ansible_host: 10.10.0.12
          swarm_data_addr: 10.20.0.12
        manager-03:
          ansible_host: 10.10.0.13
          swarm_data_addr: 10.20.0.13
    swarm_workers:
      hosts:
        worker-01:
          ansible_host: 10.10.0.21
          swarm_data_addr: 10.20.0.21
          swarm_labels:
            zone: rack-a
            storage: ssd
```

`ansible_host`는 SSH 접속 주소이고 Inventory Hostname은 자동화에서 사용할 안정적인 Node 식별자다. IP만 바뀌면 `ansible_host`를 수정하고 역할과 Variable은 유지할 수 있다.

## Network 주소 분리

| 주소 | 용도 |
|---|---|
| 관리망 IP | SSH, Ansible, 운영 접근 |
| `advertise_addr` | Manager와 Node가 Swarm Control Plane에서 알릴 주소 |
| `data_path_addr` | Overlay Network의 VXLAN Data Traffic 주소 |
| `listen_addr` | Swarm이 Control Traffic을 수신할 주소와 Port |

한 NIC 환경에서는 같은 IP를 사용할 수 있지만, 온프레미스에서 관리망과 Service Data망이 분리되어 있다면 Inventory에 각각 명시한다.

## Group Variable

```yaml
# group_vars/all.yml
docker_edition: ce
docker_version: "<검증한-version>"
swarm_listen_port: 2377
swarm_registry: registry.infra.local:5000
```

Password와 Token은 평문 Inventory에 넣지 않고 Ansible Vault나 외부 Secret Store를 사용한다. Private Key 경로도 Host별로 반복하지 말고 Control Node 표준으로 관리한다.

## Inventory 검증

```bash
ansible-inventory -i inventories/prod/hosts.yml --graph
ansible -i inventories/prod/hosts.yml all -m ping
```

`ping` Module 성공은 SSH와 Python 실행 가능성을 확인할 뿐 Swarm Port, Registry와 Storage까지 검증하지는 않는다.

## 현재 운영 기준

- Hostname은 재설치 후에도 추적 가능한 Naming Convention을 사용한다.
- Manager 수는 홀수로 유지하고 역할 변경을 Review한다.
- Label은 `zone`, `storage`, `gpu`처럼 Scheduling 의미가 있는 값만 둔다.
- Inventory 변경 이력과 실제 Node 목록의 Drift를 정기적으로 비교한다.
