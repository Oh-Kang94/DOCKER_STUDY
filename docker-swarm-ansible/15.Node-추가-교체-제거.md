# 15. Node 추가·교체·제거

## Node 추가

Inventory에 새 IP와 역할을 추가한 뒤 전체 Cluster를 다시 만들지 않고 새 Node만 처리한다.

```text
Inventory 추가
  → Preflight
  → Docker 설치
  → Swarm Join
  → Label 적용
  → Ready·Task 배치 확인
```

Playbook은 `--limit worker-04`로 실행해도 필요한 Manager에서 Token을 읽을 수 있도록 Delegation과 Host Variable 의존성을 설계한다.

## Maintenance와 교체

```bash
docker node update --availability drain worker-02
docker node ps worker-02
```

Drain 뒤 Service Task가 다른 Node에서 수렴했는지 확인한다. Standalone Container와 Local Volume Data는 Swarm이 이동시키지 않는다.

교체 Node가 같은 Hostname을 사용해도 새 Docker Engine은 새 Node ID로 가입할 수 있다. 기존 Down Node Object를 확인한 뒤 제거한다.

## Worker 제거

```bash
docker swarm leave
docker node rm worker-02
```

첫 명령은 해당 Worker에서, 두 번째는 Manager에서 실행한다. 장애 Node에 접속할 수 없을 때만 상태와 대체 Task를 확인한 뒤 강제 제거를 검토한다.

## Manager 제거

Manager는 먼저 Worker로 Demote한 뒤 제거한다.

```bash
docker node demote manager-03
docker node update --availability drain manager-03
```

Manager를 제거하기 전에 남은 Manager가 과반수 Quorum을 유지하는지 계산한다. 장애 상태에서 여러 Manager를 연속 제거하거나 새 Cluster를 초기화하지 않는다.

## Ansible에서의 원칙

- Inventory에서 사라졌다는 이유만으로 Node를 즉시 삭제하지 않는다.
- `retired_nodes` 같은 명시적 목록과 승인 단계를 둔다.
- Drain, 수렴, Demote, Leave, Remove를 단계별로 검증한다.
- Local Data와 Registry Cache 정리 여부를 별도로 결정한다.
