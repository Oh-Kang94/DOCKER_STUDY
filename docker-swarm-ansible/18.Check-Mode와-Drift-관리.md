# 18. Check Mode와 Drift 관리

## Module별 Preview 능력

모든 Ansible Module이 Check Mode와 Diff Mode를 같은 수준으로 지원하지 않는다.

| 작업 | Check·Diff 관점 |
|---|---|
| Package·Template | 일반적으로 Preview와 Diff 활용 가능, Module별 확인 필요 |
| `community.docker.docker_swarm` | 공식 문서상 Check Mode·Diff Mode 지원 |
| `community.docker.docker_stack` | 공식 문서상 Check Mode·Diff Mode 미지원 |
| Shell/Command | 별도 조건 없이는 실제 변경 여부를 추론하지 못함 |

따라서 `ansible-playbook --check --diff` 한 번만으로 Stack 배포 전체가 안전하게 Preview되었다고 판단하지 않는다.

## Stack Preview 보완

```text
Jinja Render
  → docker stack config
  → 현재 docker service inspect 수집
  → Service·Image·Config·Secret 참조 비교
  → 승인 후 docker_stack 실행
```

Rendered 파일의 정규화된 결과와 Git의 기대 상태를 비교하는 검증 Task를 만들 수 있다. Secret 값은 Diff 대상에서 제외한다.

## 멱등성 확인

```bash
ansible-playbook -i inventories/stage/hosts.yml site.yml
ansible-playbook -i inventories/stage/hosts.yml site.yml
```

두 번째 실행에서 예상 밖의 `changed`가 반복되면 Template의 비결정적 값, 순서가 바뀌는 Dictionary, Shell Task와 Module 비교 방식을 확인한다. 멱등성은 “명령이 성공함”이 아니라 “이미 원하는 상태에서는 변경하지 않음”이다.

## Drift 정책

| Drift | 처리 |
|---|---|
| 긴급 수동 변경 | Incident 기록 후 Git·Inventory에 반영하거나 원상 복구 |
| 알 수 없는 Node Label | 승인된 원본과 비교 후 제거 여부 결정 |
| Service Image Tag 변경 | 검증 Digest로 복원하고 변경 주체 조사 |
| Daemon 설정 차이 | Node를 Drain하고 순차 적용 |

자동 복구가 안전하지 않은 Manager Membership, Node 삭제와 Data Volume 변경은 보고만 하고 승인을 받는다.

## 정기 실행 구조

- CI: Syntax, Lint, Inventory와 Render 검증
- Scheduled Audit: Docker Version, Node 상태, Label과 Stack Drift 수집
- Deployment: 승인된 Artifact를 접근 가능한 Manager에 적용
- Runbook: 실패 시 관찰·원인 후보·확인·수정·Rollback 순서 기록
