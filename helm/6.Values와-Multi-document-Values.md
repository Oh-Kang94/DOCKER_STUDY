# 6. Values와 Multi-document Values

## Values 병합 우선순위

뒤에서 지정한 값이 앞의 값을 덮어쓴다.

```text
Chart values.yaml
  → 첫 번째 -f
    → 다음 -f
      → --set·--set-string·--set-json
```

```bash
helm upgrade --install api ./api-chart \
  -f values/common.yaml \
  -f values/production.yaml \
  --set-string image.tag=1.8.2
```

CI에서 긴 Object·Array를 넘길 때는 `--set-json`을 사용할 수 있지만, 반복 가능한 운영 설정은 Version 관리되는 Values 파일이 읽기 쉽다.

## Type 주의

```yaml
replicaCount: 3
service:
  port: 8080
featureEnabled: true
image:
  tag: "1.8"
```

YAML은 `1.8`, `true`, 큰 숫자 같은 값을 예상과 다른 Type으로 해석할 수 있다. Image Tag·ID·환경 변수는 문자열로 명확히 표시하고, Kubernetes Integer Field에는 문자열을 넣지 않는다.

## Helm 4 Multi-document Values

Helm 4는 하나의 Values 파일 안에 여러 YAML Document를 둘 수 있다. 뒤 Document가 앞 Document를 덮어쓰는 Layer로 동작하도록 사용한다.

```yaml
# values-production.yaml
replicaCount: 2
image:
  repository: registry.example.com/apps/api
  tag: "1.8.2"
---
replicaCount: 4
resources:
  requests:
    cpu: 250m
    memory: 256Mi
```

복잡한 환경 설정을 한 파일에서 구분할 수 있지만, 변경 책임자가 다르거나 Secret 권한이 다르면 파일을 분리하는 편이 낫다. Helm 3와 함께 사용하는 Pipeline에는 Multi-document Values 호환성을 먼저 확인한다.

## Secret 경계

Values는 Render와 Release Metadata를 통해 노출될 수 있다.

```bash
helm get values api -n apps --all
```

Password나 Private Key를 평문 Values와 Git에 저장하지 않는다. External Secrets, SOPS 같은 별도 Secret 흐름을 사용하거나 기존 Kubernetes Secret 이름만 Value로 전달한다.

```yaml
database:
  existingSecret: api-db-credentials
```

## 운영 기준

- 기본값은 안전하고 최소 권한인 상태로 둔다.
- 환경별 차이만 Override 파일에 둔다.
- `--set`은 짧은 임시 Override에 제한한다.
- 배포에 사용한 Values 파일과 Chart Version을 함께 기록한다.
