# 7. Values Schema와 Template 확장

## Schema가 필요한 이유

Template 안에서 값이 잘못되었다고 뒤늦게 실패하기보다 `values.schema.json`으로 Values의 형태와 허용 범위를 먼저 검증한다. Schema는 `helm lint`, `helm template`, `helm install`과 `helm upgrade`에서 Chart 입력의 계약 역할을 한다.

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["image", "service"],
  "properties": {
    "image": {
      "type": "object",
      "required": ["repository", "tag"],
      "properties": {
        "repository": { "type": "string", "minLength": 1 },
        "tag": { "type": "string", "minLength": 1 }
      }
    },
    "service": {
      "type": "object",
      "properties": {
        "port": { "type": "integer", "minimum": 1, "maximum": 65535 }
      }
    }
  }
}
```

`default`는 Schema의 설명용 Annotation이지 Helm Values에 값을 자동 주입하는 수단으로 가정하지 않는다. 실제 기본값은 `values.yaml`에 두고 Schema는 그 값과 사용자 Override를 검증한다.

## Template 내부의 필수값

Schema로 표현하기 어려운 조건은 Template에서 보완할 수 있다.

```yaml
image: {{ required "image.repository가 필요합니다" .Values.image.repository }}:{{ .Values.image.tag }}
replicas: {{ .Values.replicaCount | default 2 | int }}
```

- `required`는 값이 비어 있으면 명확한 오류를 만든다.
- `default`는 값이 비었을 때 Template 결과에 기본값을 사용한다.
- `int`, `quote` 같은 함수로 출력 형태를 명시한다.

## JSON Argument

복합 값을 CLI에서 넣을 때는 문자열 해석이 모호한 `--set`보다 `--set-json`이 안전하다.

```bash
helm upgrade --install api ./api-chart \
  --set-json 'extraEnv=[{"name":"LOG_LEVEL","value":"info"}]'
```

긴 객체는 명령행에 넣지 않고 별도 Values 파일로 Version 관리한다. Shell History에 남으면 안 되는 Secret도 CLI Argument로 전달하지 않는다.

## Custom Template Function

Helm 4 Plugin은 Custom Template Function을 제공할 수 있다. 조직 공통 규칙을 함수로 캡슐화할 수 있지만 Chart가 해당 Plugin 설치에 의존하게 된다.

```text
Chart Template → Helm built-in/Sprig 함수
               → 설치된 Plugin의 Custom 함수
```

Plugin 이름과 Version을 CI 및 개발 환경에 고정하고, 외부 배포용 Chart는 가능한 한 표준 함수만 사용한다.

## 현재 운영 기준

- `values.yaml`과 `values.schema.json`을 함께 변경한다.
- 숫자·Boolean을 문자열로 우회해 Schema를 무력화하지 않는다.
- 조건부 필수값은 오류 문구에 정확한 경로를 포함한다.
- Schema 검증 뒤에도 Rendered Manifest와 Kubernetes API 검증을 별도로 수행한다.
