# 5. Go Template 기본

## Action과 Pipeline

Helm Template은 Go Template에 Sprig와 Helm Function을 더한 형태다. `{{ ... }}`가 Action이며 Pipeline은 앞 결과를 다음 Function으로 전달한다.

```gotemplate
metadata:
  name: {{ include "api.fullname" . | trunc 63 | trimSuffix "-" }}
spec:
  replicas: {{ .Values.replicaCount }}
```

YAML 문자열은 `quote`, 들여쓰기는 `nindent`를 명시해 Type과 공백 오류를 줄인다.

## if, with와 range

```gotemplate
{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
{{- end }}

{{- with .Values.podAnnotations }}
annotations:
  {{- toYaml . | nindent 2 }}
{{- end }}

{{- range .Values.extraEnv }}
- name: {{ .name | quote }}
  value: {{ .value | quote }}
{{- end }}
```

`with`와 `range` 안의 `.`은 Scope가 바뀐다. Root Context가 필요하면 `$`를 사용한다.

```gotemplate
name: {{ $.Release.Name }}-{{ .name }}
```

## Built-in Object

| Object | 주요 정보 |
|---|---|
| `.Values` | 병합된 사용자 설정 |
| `.Release` | 이름·Namespace·Revision·Install 여부 |
| `.Chart` | `Chart.yaml` Metadata |
| `.Capabilities` | Kubernetes API와 Version 정보 |
| `.Files` | Chart에 포함된 일반 파일 |

`.Capabilities.APIVersions.Has`로 API 존재 여부를 분기할 수 있지만, 지나치게 많은 Version 분기는 Chart 유지보수를 어렵게 한다.

## Named Template과 include

```gotemplate
{{- define "api.fullname" -}}
{{ printf "%s-%s" .Release.Name .Chart.Name | trunc 63 | trimSuffix "-" }}
{{- end }}
```

```gotemplate
labels:
  {{- include "api.labels" . | nindent 2 }}
```

`include`는 결과를 Pipeline에 넣을 수 있어 YAML 들여쓰기에 유리하다. `required`는 반드시 받아야 하는 Value가 없을 때 명확한 오류를 만든다.

```gotemplate
repository: {{ required "image.repository is required" .Values.image.repository | quote }}
```

## Debugging 기준

- 공백 제거 기호 `{{-`와 `-}}`가 YAML 줄을 합치지 않는지 Render 결과로 확인한다.
- 복잡한 Logic을 Template에 숨기기보다 Values와 Application 설계를 단순화한다.
- `helm template --debug`로 실제 YAML을 먼저 확인한다.
