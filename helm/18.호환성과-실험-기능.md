# 18. 호환성과 실험 기능

## Helm 3에서 Helm 4로

Helm 4는 Chart API v2 Chart를 계속 지원하지만 CLI, Plugin과 Release Apply 동작에는 확인할 변화가 있다.

| 점검 대상 | 확인 내용 |
|---|---|
| Chart | API v2 Render·Lint 결과, 폐기된 Kubernetes API |
| Release | Helm 3에서 만든 Revision의 Apply 방식 Latching |
| CLI | `--atomic`→`--rollback-on-failure`, `--force`→`--force-replace` |
| Plugin | Helm 4 SDK·Plugin Type 대응 Version |
| Post-renderer | 실행 파일 경로가 아닌 Plugin 이름 기반 사용 |
| 자동화 | 출력 형식과 Exit Code를 가정한 Script |

## 안전한 전환 순서

1. Helm 3의 Release, Chart, Values와 Plugin 목록을 Inventory로 만든다.
2. 같은 Chart를 Helm 4로 Render해 결과를 비교한다.
3. 비운영 Cluster에서 Install·Upgrade·Rollback·Uninstall을 검증한다.
4. Helm 3에서 생성한 Release의 Apply 방식과 Field Ownership을 확인한다.
5. CI Image와 운영 Runbook의 명령을 Helm 4 기준으로 바꾼다.
6. 일부 Release부터 단계적으로 전환하고 복구 기준을 기록한다.

Helm 3 지원 종료 일정 때문에 전환을 미루기보다, Plugin과 자동화 호환성을 포함한 Migration 기간을 확보한다.

## Chart API v3

Helm 4의 Chart API v3는 실험 기능이다. Chart API v2가 신규 운영 Chart의 기본값이며, v3는 기능 검증과 피드백 목적의 별도 Branch나 Test Registry에서만 평가한다.

```yaml
# 운영 기본
apiVersion: v2
name: api
version: 1.0.0
```

실험 API는 호환성, Schema와 Tooling 지원이 바뀔 수 있다. Production 표준으로 선택하기 전에 Stable 선언과 Migration 경로를 다시 확인한다.

## Version 정책

- Helm Client와 CI Image Version을 명시적으로 고정한다.
- Kubernetes 지원 Version 범위를 Chart Metadata와 Test Matrix에 반영한다.
- Chart Consumer가 Helm 3을 계속 사용한다면 배포 대상별 호환 범위를 문서화한다.
- Helm Release Downgrade가 필요할 때 Metadata 호환성을 추측하지 말고 공식 Migration 절차를 따른다.
