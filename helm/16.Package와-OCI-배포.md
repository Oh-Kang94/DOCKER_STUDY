# 16. Package와 OCI 배포

## Chart Package

```bash
helm lint ./api-chart
helm package ./api-chart --destination dist/
```

`Chart.yaml`의 `version`은 Chart Package Version이고 `appVersion`은 포함된 Application의 표시용 Version이다. Template에서 `appVersion`을 Image Tag로 강제하면 Image Release와 Chart Release가 불필요하게 결합될 수 있다.

```text
api-chart-1.4.0.tgz
          └─ Chart version 1.4.0
             appVersion: 2.7.3
```

## OCI Registry

```bash
helm registry login registry.infra.local
helm push dist/api-chart-1.4.0.tgz oci://registry.infra.local/helm
helm pull oci://registry.infra.local/helm/api-chart --version 1.4.0
```

OCI Reference의 Basename과 Tag는 Chart 이름과 Semantic Version에 맞춰 관리한다. Registry Credential을 명령행 인수나 CI Log에 노출하지 않는다.

## Digest 기반 사용

Tag는 Registry 정책에 따라 이동할 수 있지만 Digest는 Content를 식별한다. Helm 4는 OCI Digest 기반 설치 흐름을 지원하므로 Production에서는 검토한 Artifact의 Digest를 배포 기록에 남긴다.

```bash
helm install api \
  oci://registry.infra.local/helm/api-chart@sha256:<verified-digest> \
  --namespace apps
```

```text
Git commit → Chart package → OCI digest
                          └→ Release revision과 함께 기록
```

Digest는 누가 만들었는지를 증명하지 않는다. Signature, Provenance, Registry 접근 제어와 CI Identity를 함께 사용한다.

## 온프레미스 Registry 점검

- 모든 배포 실행 환경에서 Registry DNS와 TLS가 동작하는가?
- 사설 CA가 Helm 실행 Host의 Trust Store에 설치되어 있는가?
- Chart Project와 Container Image Project의 권한이 분리되어 있는가?
- Immutable Tag 또는 삭제 방지 정책이 있는가?
- Backup과 Disaster Recovery에 Chart Artifact가 포함되는가?

`--plain-http`나 TLS 검증 우회는 폐쇄망이라는 이유만으로 운영 기본값으로 두지 않는다.
