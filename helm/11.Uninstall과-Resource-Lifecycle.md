# 11. Uninstall과 Resource Lifecycle

## Uninstall의 범위

```bash
helm uninstall api -n apps --dry-run
helm uninstall api -n apps
```

Uninstall은 Release가 관리하는 Resource와 Release Metadata를 삭제한다. 그러나 모든 관련 데이터가 자동으로 사라진다고 가정하면 안 된다.

| 대상 | 남을 수 있는 이유 |
|---|---|
| PVC·외부 Volume | Data 보존 정책과 StorageClass Reclaim Policy |
| CRD | `crds/`의 CRD를 Helm이 일반 Resource처럼 삭제하지 않음 |
| Hook Resource | Hook Delete Policy가 없거나 실행이 중단됨 |
| `resource-policy: keep` Resource | 명시적으로 삭제 방지 |
| 외부 DB·DNS·Load Balancer | 별도 Controller나 시스템이 관리 |

## 삭제 전 확인

```bash
helm get manifest api -n apps
kubectl get pvc -n apps
kubectl get all,configmap,secret -n apps \
  -l app.kubernetes.io/instance=api
```

삭제 전에 DB Dump, PVC Snapshot과 복구 절차가 실제로 유효한지 확인한다. Release 삭제는 Backup이 아니다.

## Resource Policy

```yaml
metadata:
  annotations:
    helm.sh/resource-policy: keep
```

`keep`은 중요한 Resource를 남기지만 이후 Helm의 관리 밖에 고아 Resource가 생길 수 있다. 소유자, 수동 삭제 조건과 재설치 시 이름 충돌 처리까지 Runbook에 기록한다.

## CRD Lifecycle

`crds/`에 둔 CRD는 Template보다 먼저 설치되며 Upgrade·삭제를 일반 Resource처럼 관리하지 않는다. CRD Schema 변경과 기존 Custom Resource Data Migration은 Controller 공급자의 절차를 따른다. CRD 삭제는 Cluster 전체의 Custom Resource를 잃을 수 있으므로 Chart 정리 작업에 묶지 않는다.

## 안전한 종료 순서

1. Traffic을 차단하거나 Maintenance 상태로 전환한다.
2. Stateful Data와 외부 의존성을 Backup한다.
3. 남겨야 할 PVC·CRD·Secret 목록을 확정한다.
4. Uninstall Dry Run과 대상 Namespace를 확인한다.
5. 삭제 뒤 잔여 Resource와 Cloud/On-premise 자원을 점검한다.
6. 복구가 필요하면 새 Release 설치와 Data Restore를 수행한다.
