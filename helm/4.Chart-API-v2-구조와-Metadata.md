# 4. Chart API v2 구조와 Metadata

## 기본 Directory 구조

```text
api-chart/
├── Chart.yaml
├── Chart.lock
├── values.yaml
├── values.schema.json
├── charts/
├── crds/
├── templates/
│   ├── _helpers.tpl
│   ├── deployment.yaml
│   ├── service.yaml
│   └── NOTES.txt
└── .helmignore
```

`templates/`는 Values를 받아 Kubernetes Manifest를 만들고, `charts/`에는 Dependency가 놓인다. `crds/`의 CRD는 일반 Template보다 먼저 처리되며 Upgrade·Delete Lifecycle이 다르다.

## Chart.yaml

```yaml
apiVersion: v2
name: api
description: Internal API service
type: application
version: 0.3.0
appVersion: "1.8.2"
kubeVersion: ">=1.33.0-0"
```

- `apiVersion: v2`는 Helm Chart Format Version이다.
- `type: application`은 배포 가능한 Chart다.
- `type: library`는 공통 Template을 제공하고 자체 Resource를 배포하지 않는다.
- `version` 변경 없이 Package 내용을 바꾸면 같은 좌표가 다른 Artifact를 가리켜 재현성이 깨진다.

## Template 보조 파일

`_helpers.tpl`에는 이름, Label 같은 Named Template을 둔다. `NOTES.txt`는 설치 후 사용자에게 보여줄 확인 명령을 만든다. `.helmignore`는 Package에서 제외할 파일을 정의한다.

```gotemplate
{{- define "api.labels" -}}
app.kubernetes.io/name: {{ .Chart.Name }}
app.kubernetes.io/instance: {{ .Release.Name }}
helm.sh/chart: {{ printf "%s-%s" .Chart.Name .Chart.Version }}
{{- end }}
```

Named Template 이름은 Subchart까지 전역이므로 `api.labels`처럼 Chart 이름으로 Namespace를 만든다.

## Chart API v2를 사용하는 이유

Helm 4에서도 기존 v2 Chart가 기본 운영 형식이다. Chart API v3는 실험 기능이며 환경 변수와 별도 생성 Option이 필요하다. 신규 Production Chart에 실험 Format을 사용하지 않는다.

```bash
helm create api-chart
helm lint api-chart
helm package api-chart
```

## 유지보수 기준

- Resource 종류별로 Template 파일을 분리한다.
- `version`과 Application Image Version을 독립적으로 변경한다.
- 생성 결과에 Source와 Version Label을 남긴다.
- Package에 Credential, Private Key와 불필요한 파일을 포함하지 않는다.
