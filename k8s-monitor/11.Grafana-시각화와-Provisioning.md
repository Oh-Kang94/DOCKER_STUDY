# 11. Grafana 시각화와 Provisioning

## Grafana의 역할

Grafana는 Prometheus·Thanos 같은 Data Source를 Query해 Dashboard와 Alert UI를 제공한다. Metric 원본을 수집하는 Prometheus의 대체재가 아니다.

## Kubernetes Service 유형

기본은 ClusterIP다.

```yaml
apiVersion: 1
kind: Service
metadata:
  name: grafana
  namespace: monitoring
spec:
  type: ClusterIP
  selector:
    app.kubernetes.io/name: grafana
  ports:
    - name: http
      port: 80
      targetPort: 3000
```

Local 접근:

```bash
kubectl port-forward service/grafana -n monitoring 3000:80
```

LoadBalancer는 빠르지만 Grafana가 직접 외부에 노출된다. Production은 Gateway API·TLS·SSO·Authorization·NetworkPolicy를 적용하고 Public IP가 꼭 필요한지 검토한다.

## Data Source Provisioning

```yaml
apiVersion: v1
datasources:
  - name: Thanos
    uid: thanos
    type: prometheus
    access: proxy
    url: http://thanos-query.monitoring.svc:9090
    isDefault: true
    editable: false
    jsonData:
      prometheusType: Thanos
```

이 YAML은 Grafana Provisioning File 내용이며 Kubernetes Resource가 아니다. ConfigMap에 담아 `/etc/grafana/provisioning/datasources`에 Mount한다.

## Dashboard Provisioning

```yaml
apiVersion: 1
providers:
  - name: platform
    folder: Kubernetes
    type: file
    disableDeletion: false
    allowUiUpdates: false
    updateIntervalSeconds: 30
    options:
      path: /var/lib/grafana/dashboards/platform
```

Dashboard JSON은 ConfigMap, Sidecar, Git Sync 또는 Grafana Operator/Terraform 방식 중 하나를 선택해 Git에서 관리한다. UI 변경은 Provisioning Source Update 때 덮어써질 수 있다.

## Dashboard ID 자동화

Grafana.com Dashboard ID를 UI에 입력해 Import할 수 있지만 Runtime마다 최신 Revision을 자동 다운로드하면 재현성이 없다.

권장 흐름:

1. Dashboard ID와 Revision을 검토한다.
2. JSON을 Export해 Repository에 저장한다.
3. Data Source UID·Variable을 환경에 맞게 수정한다.
4. ConfigMap 또는 Provisioning Tool로 배포한다.
5. Upgrade 시 JSON Diff와 Query 호환성을 Review한다.

API 자동화에는 Legacy API Key보다 Grafana Service Account Token을 사용하고 최소 권한·회전을 적용한다.

## Dashboard 구성

- Cluster Overview: Node·Pod·Control Plane
- Workload: Desired/Available·Restart·CPU·Memory
- Application RED: Rate·Error·Duration
- Storage: PVC·Capacity·Latency·Error
- Monitoring Stack: Scrape Failure·Rule Error·TSDB·Thanos Store

각 Panel은 단위, Legend, Threshold와 “No data” 의미를 명확히 한다.

## Deployment와 Persistence

Grafana 내부 DB에는 User, Folder, Dashboard와 Annotation 상태가 저장될 수 있다. Provisioning만으로 복구 가능한 범위와 PVC·외부 Database Backup이 필요한 범위를 구분한다.

```yaml
volumeMounts:
  - name: data
    mountPath: /var/lib/grafana
volumes:
  - name: data
    persistentVolumeClaim:
      claimName: grafana-data
```

다중 Replica는 단순 RWO SQLite PVC 공유가 아니라 지원되는 외부 Database와 Session·Plugin 호환성을 검토한다.

## 보안과 운영

- 기본 Admin Password를 Secret으로 주입하고 즉시 회전한다.
- Anonymous Access를 Production 기본으로 켜지 않는다.
- SSO Group과 Folder·Data Source 권한을 연결한다.
- Plugin Version과 Signature를 관리한다.
- Dashboard Query가 과도한 Range·Cardinality를 만들지 않게 제한한다.
- Grafana Health, Login Failure와 Alert Evaluation을 모니터링한다.
