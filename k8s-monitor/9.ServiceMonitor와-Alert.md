# 9. Prometheus 수집과 Alert

## ServiceMonitor

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: shop
  namespace: monitoring
  labels:
    monitoring.example.com/stack: platform
spec:
  namespaceSelector:
    matchNames:
      - apps
  selector:
    matchLabels:
      app.kubernetes.io/name: shop
  endpoints:
    - port: metrics
      path: /metrics
      interval: 30s
      scrapeTimeout: 10s
```

`selector`는 Pod가 아니라 Service Label을 선택하고 `port`는 Service Port 이름을 참조한다. ServiceMonitor 자체가 Prometheus의 `serviceMonitorSelector`에도 선택되어야 한다.

## PodMonitor

Service가 필요 없는 Target은 PodMonitor를 사용할 수 있다.

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PodMonitor
metadata:
  name: worker
  namespace: monitoring
  labels:
    monitoring.example.com/stack: platform
spec:
  namespaceSelector:
    matchNames:
      - apps
  selector:
    matchLabels:
      app.kubernetes.io/name: worker
  podMetricsEndpoints:
    - port: metrics
      interval: 30s
```

Annotation 기반 자동 Scrape는 구현체별 Convention이라 Kubernetes 표준이 아니다. 신규 Operator 구성에서는 ServiceMonitor·PodMonitor로 수집 의도를 명시한다.

## Target 확인

```promql
up{namespace=\"apps\"}
```

`up == 0`이면 Prometheus Target Discovery, Endpoint, NetworkPolicy, TLS·인증과 `/metrics` 응답 시간을 확인한다.

## 기본 PromQL

Request Rate:

```promql
sum by (route) (
  rate(shop_http_requests_total[5m])
)
```

Error Ratio:

```promql
sum(rate(shop_http_requests_total{status=~\"5..\"}[5m]))
/
sum(rate(shop_http_requests_total[5m]))
```

P95 Latency:

```promql
histogram_quantile(
  0.95,
  sum by (le, route) (
    rate(shop_http_request_duration_seconds_bucket[5m])
  )
)
```

## PrometheusRule

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: shop
  namespace: monitoring
  labels:
    monitoring.example.com/stack: platform
spec:
  groups:
    - name: shop.rules
      rules:
        - record: job:shop_http_error_ratio:rate5m
          expr: |
            sum(rate(shop_http_requests_total{status=~\"5..\"}[5m]))
            /
            sum(rate(shop_http_requests_total[5m]))
        - alert: ShopHighErrorRatio
          expr: job:shop_http_error_ratio:rate5m > 0.05
          for: 10m
          labels:
            severity: page
          annotations:
            summary: Shop의 5xx 비율이 10분간 5%를 초과했습니다.
            runbook_url: https://runbooks.example.com/shop/high-error-ratio
```

Recording Rule은 비싼 Query와 Metric 이름 변화를 Dashboard 앞에서 안정화한다.

## Alert 설계

- `for`로 짧은 Spike와 Flapping을 줄인다.
- Page는 즉시 사람이 행동해야 하는 사용자 영향에만 사용한다.
- Alertmanager Route·Grouping·Inhibition으로 중복을 줄인다.
- 모든 Alert에 Owner, Summary, Dashboard와 Runbook을 연결한다.
- Rule은 `promtool test rules`로 Input Series와 예상 Alert를 Test한다.

## 수집 보안과 비용

- Cross-namespace Monitor 생성 권한을 제한한다.
- Metric Endpoint NetworkPolicy가 Prometheus Namespace를 허용해야 한다.
- Relabeling으로 Secret·고 Cardinality Label을 무작정 복제하지 않는다.
- Scrape Interval을 짧게 할수록 Sample·Network·Storage 비용이 증가한다.
