# 6. kube-state-metrics

## 무엇을 수집하는가

kube-state-metrics, KSM은 Kubernetes API Object를 Watch하고 Desired·Current 상태를 Prometheus Metric으로 변환한다.

```text
kube_deployment_spec_replicas
kube_deployment_status_replicas_available
kube_pod_status_phase
kube_pod_container_status_restarts_total
kube_persistentvolumeclaim_status_phase
```

CPU·Memory 실사용량을 수집하는 Metrics Server나 kubelet/cAdvisor와 역할이 다르다.

## 구조

```mermaid
flowchart LR
    A[kube-apiserver]
    K[kube-state-metrics<br/>Informer Cache]
    E[/metrics :8080]
    P[Prometheus]
    A -->|list·watch| K --> E -->|scrape| P
```

Object가 삭제되면 KSM Endpoint에서도 사라진다. History는 Prometheus가 저장한다.

## 설치 YAML의 핵심

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: kube-state-metrics
  namespace: monitoring
spec:
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: kube-state-metrics
  template:
    metadata:
      labels:
        app.kubernetes.io/name: kube-state-metrics
    spec:
      serviceAccountName: kube-state-metrics
      containers:
        - name: kube-state-metrics
          image: registry.k8s.io/kube-state-metrics/kube-state-metrics:<compatible-version>
          ports:
            - name: metrics
              containerPort: 8080
            - name: telemetry
              containerPort: 8081
```

실제 배포에는 Service, ClusterRole·Binding과 Probe가 추가로 필요하다. Kubernetes Version Compatibility Matrix에 맞는 Release나 kube-prometheus-stack이 고정한 조합을 사용한다.

## Docker에서 가능한가?

Binary·Container로 실행할 수는 있지만 kubeconfig와 RBAC이 필요하다. Cluster 내부 Deployment가 Network·Credential Rotation과 Service Discovery에 적합하다. 일반 Docker 상태를 모니터링하는 Exporter가 아니다.

## 확인

```bash
kubectl port-forward service/kube-state-metrics \
  -n monitoring 8080:8080
curl --fail http://127.0.0.1:8080/metrics \
  | grep kube_deployment_status_replicas_available
```

## Cardinality와 RBAC

Kubernetes Label을 Metric Label로 허용하면 Series가 급증할 수 있다. Allowlist와 Resource Filter를 사용하고 Secret Object를 Watch할 필요가 있는지 검토한다. Namespace 한정 모니터링은 RoleBinding과 `--namespaces`·`--resources`로 범위를 줄일 수 있다.

## 대표 비교 Query

```promql
kube_deployment_spec_replicas
-
kube_deployment_status_replicas_available
```

`kubectl`은 사람이 이해하기 위한 Heuristic을 적용할 수 있지만 KSM은 API Object의 Raw State를 Metric으로 나타내므로 결과 표현이 다를 수 있다.
