# 3. CRD와 OpenAPI Schema 정의

## 현재 CRD 구조

`apiextensions.k8s.io/v1`에서는 예전의 최상위 `spec.validation` 대신 각 Version 아래 `spec.versions[].schema.openAPIV3Schema`에 Schema를 정의한다.

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: webapps.platform.example.com
spec:
  group: platform.example.com
  scope: Namespaced
  names:
    plural: webapps
    singular: webapp
    kind: WebApp
    shortNames:
      - wa
  versions:
    - name: v1alpha1
      served: true
      storage: true
      schema:
        openAPIV3Schema:
          type: object
          required:
            - spec
          properties:
            spec:
              type: object
              required:
                - image
              properties:
                image:
                  type: string
                  minLength: 1
                replicas:
                  type: integer
                  minimum: 1
                  maximum: 20
                  default: 1
                port:
                  type: integer
                  minimum: 1
                  maximum: 65535
                  default: 8080
            status:
              type: object
              properties:
                readyReplicas:
                  type: integer
                  minimum: 0
                phase:
                  type: string
                  enum:
                    - Progressing
                    - Ready
                    - Degraded
                observedGeneration:
                  type: integer
                  format: int64
                conditions:
                  type: array
                  x-kubernetes-list-type: map
                  x-kubernetes-list-map-keys:
                    - type
                  items:
                    type: object
                    required:
                      - type
                      - status
                      - reason
                      - message
                      - lastTransitionTime
                    properties:
                      type:
                        type: string
                      status:
                        type: string
                        enum:
                          - "True"
                          - "False"
                          - Unknown
                      reason:
                        type: string
                      message:
                        type: string
                      observedGeneration:
                        type: integer
                        format: int64
                      lastTransitionTime:
                        type: string
                        format: date-time
      subresources:
        status: {}
      additionalPrinterColumns:
        - name: Image
          type: string
          jsonPath: .spec.image
        - name: Desired
          type: integer
          jsonPath: .spec.replicas
        - name: Ready
          type: integer
          jsonPath: .status.readyReplicas
        - name: Phase
          type: string
          jsonPath: .status.phase
```

## metadata.name

CRD 이름은 반드시 `<plural>.<group>` 형식이다.

```text
plural: webapps
group:  platform.example.com
metadata.name: webapps.platform.example.com
```

소유한 DNS Domain을 Group에 사용하고 `k8s.io`·`kubernetes.io` 같은 예약 영역을 사용하지 않는다.

## spec.group와 scope

CR API Endpoint는 다음 형태가 된다.

```text
/apis/platform.example.com/v1alpha1/namespaces/apps/webapps
```

`scope`는 `Namespaced` 또는 `Cluster`다. 팀별 Object라면 Namespaced를 우선하고, Cluster 전체를 실제로 대표하는 Object만 Cluster Scope로 둔다.

## spec.names

| Field | 예시 | 사용 위치 |
|---|---|---|
| `plural` | `webapps` | REST Resource와 kubectl |
| `singular` | `webapp` | CLI와 Discovery |
| `kind` | `WebApp` | YAML `kind` |
| `shortNames` | `wa` | `kubectl get wa` |
| `categories` | `all` | 선택적 Category |

Plural과 Kind는 API 출시 후 변경하기 어렵다. 약어보다 충돌하지 않는 명확한 이름을 먼저 설계한다.

## versions

| Field | 의미 |
|---|---|
| `name` | `v1alpha1`, `v1beta1`, `v1` 같은 API Version |
| `served` | 해당 Version Endpoint 제공 여부 |
| `storage` | etcd 저장에 사용하는 Version |

`storage: true`는 정확히 하나여야 한다. 여러 Version을 동시에 Serve할 때 Schema가 다르면 Conversion Webhook이 필요할 수 있다.

## required와 Validation

`required`는 해당 Object Level의 Field 이름 배열이다. `spec.image`를 필수로 만들려면 `spec` Schema 안에 `required: [image]`를 둔다.

```yaml
spec:
  type: object
  required:
    - image
  properties:
    image:
      type: string
      pattern: '^.+@sha256:[a-f0-9]{64}$'
```

Type, enum, minimum, maximum, pattern과 length로 표현 가능한 규칙은 Webhook보다 OpenAPI Schema를 우선한다.

## CEL Validation

Field 사이 관계는 `x-kubernetes-validations`로 표현할 수 있다.

```yaml
spec:
  type: object
  properties:
    minReplicas:
      type: integer
      minimum: 1
    maxReplicas:
      type: integer
      minimum: 1
  x-kubernetes-validations:
    - rule: self.minReplicas <= self.maxReplicas
      message: minReplicas는 maxReplicas보다 클 수 없습니다.
```

간단한 불변식은 CEL을 사용하고 외부 Network 조회가 필요한 검증만 Admission Webhook을 검토한다.

## Pruning과 Unknown Field

Structural Schema에 정의하지 않은 Field는 기본적으로 저장 과정에서 제거될 수 있다. 무조건 보존하려고 `x-kubernetes-preserve-unknown-fields`를 넓게 사용하면 오타 검출과 Version Migration이 어려워진다.

## 적용 전 확인

```bash
kubectl apply --dry-run=server -f webapp-crd.yaml
kubectl apply -f webapp-crd.yaml
kubectl wait --for=condition=Established \
  crd/webapps.platform.example.com

kubectl explain webapp.spec
kubectl api-resources --api-group=platform.example.com
```

CR 예시도 Server-side Dry Run으로 Schema 거부 결과를 확인한다.

```bash
kubectl apply --dry-run=server -f webapp-invalid.yaml
```

예상 오류:

```text
spec.replicas: Invalid value: 0: spec.replicas in body should be greater than or equal to 1
```
