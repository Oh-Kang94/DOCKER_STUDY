# 2. Docker Compose 사용 방법

## 프로젝트, 서비스, 컨테이너

Compose를 사용할 때는 프로젝트, 서비스, 컨테이너의 관계를 먼저 이해해야 한다.

```text
프로젝트
├── web 서비스
│   └── web 컨테이너
└── db 서비스
    └── db 컨테이너
```

### 프로젝트

프로젝트는 하나의 Compose 파일로 관리하는 전체 애플리케이션 단위이다. 서비스뿐 아니라 해당 서비스가 사용하는 네트워크와 볼륨도 프로젝트에 포함된다.

기본 프로젝트 이름은 Compose 파일이 있는 디렉터리 이름이다. 예를 들어 `myapp` 디렉터리에서 실행하면 컨테이너와 네트워크는 보통 다음과 같은 이름을 갖는다.

```text
myapp-web-1
myapp-db-1
myapp_default
myapp_db-data
```

프로젝트 이름이 다르면 같은 `web`, `db` 서비스 이름을 사용해도 서로 다른 리소스로 관리할 수 있다.

### 서비스

서비스는 동일한 설정으로 실행되는 컨테이너의 설계도이다. 서비스 정의에는 이미지, 빌드 방법, 명령, 환경 변수, 포트, 볼륨과 네트워크 등이 들어간다.

```yaml
services:
  web:
    image: nginx:alpine
```

여기서 `web`은 서비스 이름이고 `nginx:alpine`은 해당 서비스의 컨테이너가 사용할 이미지이다. 같은 네트워크에 있는 다른 서비스는 `web`이라는 이름으로 접근할 수 있다.

### 컨테이너

컨테이너는 서비스 정의를 바탕으로 Docker Engine이 실제로 만든 실행 단위이다. 일반적으로 서비스 하나당 컨테이너 하나가 만들어지지만 `--scale` 옵션으로 여러 개를 실행할 수도 있다.

```bash
docker compose up -d --scale web=3
```

`ports`에 고정된 호스트 포트가 있으면 같은 호스트 포트를 여러 컨테이너가 동시에 사용할 수 없으므로 scale 시 포트 충돌을 고려해야 한다.

## 기본 CLI 구조

```text
docker compose [공통 옵션] 명령 [명령 옵션] [서비스...]
```

예를 들어 다음 명령은 `dev`라는 프로젝트 이름으로 `compose.dev.yaml` 파일을 사용해 `web` 서비스만 백그라운드에서 실행한다.

```bash
docker compose -p dev -f compose.dev.yaml up -d web
```

### 자주 사용하는 공통 옵션

| 옵션 | 의미 | 예시 |
| --- | --- | --- |
| `-f`, `--file` | 사용할 Compose 파일 지정 | `-f compose.yaml` |
| `-p`, `--project-name` | 프로젝트 이름 지정 | `-p myapp-dev` |
| `--env-file` | 변수 치환에 사용할 환경 파일 지정 | `--env-file .env.dev` |
| `--profile` | 선택적인 서비스 그룹 활성화 | `--profile debug` |
| `--dry-run` | 가능한 명령에서 변경 계획을 미리 표시 | `--dry-run up -d` |

`-f` 옵션은 여러 번 사용할 수 있다. 뒤에 지정한 파일이 앞 파일의 설정을 추가하거나 덮어쓴다.

```bash
docker compose \
  -f compose.yaml \
  -f compose.dev.yaml \
  config
```

## 주요 명령어

### 버전 확인

```bash
docker compose version
```

현재 설치된 Compose CLI 버전을 확인한다.

### Compose 파일 확인: `config`

```bash
docker compose config
docker compose config --quiet
```

`config`는 여러 Compose 파일을 병합하고 환경 변수를 치환한 뒤 Docker Engine에 적용될 최종 모델을 출력한다. `--quiet` 또는 `-q`를 사용하면 출력 없이 구성의 유효성만 검사한다.

```bash
docker compose config --services
docker compose config --images
```

각각 최종 구성에 포함된 서비스 이름과 이미지 이름만 확인할 때 사용한다.

### 이미지 준비: `pull`, `build`

```bash
docker compose pull
docker compose pull db

docker compose build
docker compose build --no-cache web
```

- `pull`: `image`에 정의된 이미지를 레지스트리에서 내려받는다.
- `build`: `build`에 정의된 Dockerfile로 이미지를 만든다.
- 명령 마지막에 서비스 이름을 지정하면 해당 서비스만 처리한다.

### 생성 및 실행: `up`

```bash
docker compose up
docker compose up -d
docker compose up -d --build
```

`up`은 필요한 이미지, 네트워크, 볼륨과 컨테이너를 준비하고 서비스를 실행한다. 포그라운드로 실행하면 여러 서비스의 로그가 함께 표시되고 `Ctrl+C`로 종료할 때 컨테이너도 중지된다. `-d`를 사용하면 백그라운드에서 계속 실행한다.

| 옵션 | 의미 |
| --- | --- |
| `-d`, `--detach` | 백그라운드에서 실행 |
| `--build` | 실행 전에 필요한 이미지 빌드 |
| `--pull always` | 실행 전에 항상 이미지 pull 시도 |
| `--force-recreate` | 설정 변경이 없어도 컨테이너 재생성 |
| `--no-recreate` | 이미 존재하는 컨테이너를 재생성하지 않음 |
| `--remove-orphans` | 현재 파일에 더 이상 정의되지 않은 서비스 컨테이너 제거 |
| `--scale SERVICE=N` | 특정 서비스의 컨테이너 수 지정 |

Compose는 서비스 설정이나 이미지가 바뀌면 기존 컨테이너를 중지하고 새 컨테이너로 재생성한다. 연결된 named volume의 데이터는 컨테이너가 재생성되어도 유지된다.

### 상태 확인: `ps`

```bash
docker compose ps
docker compose ps --all
```

`ps`는 현재 프로젝트의 컨테이너 상태와 포트 연결을 표시한다. 기본적으로 실행 중인 컨테이너만 보이며 `--all` 또는 `-a`를 사용하면 종료된 컨테이너도 포함한다.

### 로그 확인: `logs`

```bash
docker compose logs
docker compose logs -f --tail 100 web
```

| 옵션 | 의미 |
| --- | --- |
| `-f`, `--follow` | 새로운 로그를 계속 출력 |
| `--tail N` | 마지막 N줄만 출력 |
| `-t`, `--timestamps` | 로그에 타임스탬프 표시 |
| 서비스 이름 | 지정한 서비스 로그만 출력 |

### 실행 중인 컨테이너에서 명령 실행: `exec`

```bash
docker compose exec db psql -U study -d app
docker compose exec web sh
```

`exec`는 이미 실행 중인 서비스 컨테이너 안에서 명령을 실행한다.

### 일회성 컨테이너 실행: `run`

```bash
docker compose run --rm web ./manage.py migrate
```

`run`은 서비스 설정을 이용해 일회성 컨테이너를 새로 만든다. 기본적으로 서비스에 정의된 `ports`는 게시하지 않으며 `--rm`을 사용하면 명령 종료 후 컨테이너를 제거한다.

### 중지와 재시작: `stop`, `start`, `restart`

```bash
docker compose stop
docker compose start
docker compose restart web
```

- `stop`: 컨테이너를 삭제하지 않고 중지한다.
- `start`: 중지되어 있는 기존 컨테이너를 다시 시작한다.
- `restart`: 컨테이너를 다시 시작하지만 Compose 파일의 변경 내용을 반영하지 않는다. 설정 변경을 적용하려면 `docker compose up -d`를 사용한다.

### 프로젝트 정리: `down`

```bash
docker compose down
docker compose down --volumes
```

`down`은 프로젝트의 서비스 컨테이너와 Compose가 만든 네트워크를 중지하고 제거한다. 기본적으로 named volume과 external 리소스는 제거하지 않는다.

| 옵션 | 의미 |
| --- | --- |
| `-v`, `--volumes` | Compose 파일의 named volume과 익명 볼륨도 제거 |
| `--rmi local` | 사용자 지정 태그가 없는 로컬 이미지 제거 |
| `--rmi all` | 서비스에서 사용하는 모든 이미지 제거 |
| `--remove-orphans` | 현재 파일에 정의되지 않은 서비스 컨테이너도 제거 |

`--volumes`는 데이터베이스 데이터까지 삭제할 수 있으므로 사용 전에 대상 볼륨을 확인해야 한다.

## 비슷한 명령 구분

| 구분 | 차이 |
| --- | --- |
| `up` / `start` | `up`은 구성을 반영해 생성·재생성할 수 있고, `start`는 기존 컨테이너만 시작한다. |
| `stop` / `down` | `stop`은 컨테이너를 남기고, `down`은 컨테이너와 프로젝트 네트워크를 제거한다. |
| `exec` / `run` | `exec`는 실행 중인 컨테이너를 사용하고, `run`은 일회성 컨테이너를 새로 만든다. |
| `build` / `up --build` | `build`는 이미지만 만들고, `up --build`는 빌드 후 서비스까지 실행한다. |
| `restart` / `up -d` | `restart`는 설정 변경을 반영하지 않고, `up -d`는 변경된 구성을 비교해 필요한 컨테이너를 재생성한다. |

## 기본 작업 흐름 예시

```bash
# 1. 파일 문법과 변수 치환 결과 확인
docker compose config --quiet

# 2. 이미지 준비 후 백그라운드 실행
docker compose up -d --build

# 3. 상태와 로그 확인
docker compose ps
docker compose logs -f --tail 100

# 4. 설정을 수정했다면 다시 반영
docker compose up -d

# 5. 컨테이너와 프로젝트 네트워크 정리
docker compose down
```
